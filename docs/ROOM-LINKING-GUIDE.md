# ⚠️ ルーム「連携」ガイド（必読）

---

## 🔓 セキュリティ注意 — 自動連携は「承認なし」で行われます

> ### このシステムの既定動作
>
> **店舗 Webhook でメッセージを受信したルームは、管理者の確認・承認なしで自動的に連携されます。**
>
> | 項目 | 内容 |
> |------|------|
> | **いつ** | ① LINE からその店舗 Webhook に届いたとき（`line-webhook`）／ ② 管理画面が Webhook 状態を取得するとき（`GET /receipts/webhook-status`） |
> | **何が起きる** | `room_summary_settings` に登録され、**売上中間・月末レポートの送信先**など店舗既定の権限が付く |
> | **手動連携との違い** | 以前の「一括連携」ボタンは確認ダイアログあり → **自動連携にはダイアログがない** |
>
> ### セキュリティが下がる理由（運用リスク）
>
> - **誤った Webhook URL** に届いたグループも、その店舗の管理ルームとして登録され得る  
> - **テスト用・一時的なトーク**も、受信すれば送信先候補になる  
> - **別店舗に既に登録済み**のルームは上書きしないが、未登録のルームは無条件に近い形で承認される  
> - 管理画面から「ゴミ箱へ」したあとでも、**復元しないまま Webhook を受信しても自動では戻りません**（`line_room_dismissed`）
> - ゴミ箱から **復元** すると一覧へ戻る。**完全削除**はメッセージ等を消すが、再連携防止のため dismiss は残す。店舗の予約・売上は消さない
>
> ### 無効化するには
>
> Supabase Edge Functions（`line-webhook` と `admin-api`）にシークレットを設定:
>
> ```text
> RECEIPT_ROOM_AUTO_LINK=0
> ```
>
> （未設定・`1`・空以外の false 系以外は **有効**）

---

## ⚠️ グループに Bot を2体入れられない（LINE 仕様）

**1つの招待グループ／複数人トークに公式 Bot は1体まで**です。すでに別 Bot がいると2体目は参加できず「すぐ退出」したように見えます（当システムの自動退出ではありません）。  
Bot が **残って無反応** なら **ルーム承認待ち** の可能性 → 管理 Bot で **許可ルーム**。  
→ [**LINE-GROUP-BOT-IMPORTANT.md**](./LINE-GROUP-BOT-IMPORTANT.md)

## 📌 結論（30 秒）

| 質問 | 答え |
|------|------|
| **連携しないとどうなる？** | 自動連携 **ON** 時は、受信後しばらくで連携されるのが通常。OFF 時はレポート送信先にならない |
| **自動連携はある？** | **ある（既定 ON）** — **連携**に管理者承認は不要。上記セキュリティ注意を参照 |
| **手動連携は？** | 残っている未連携用に **一括連携** ボタンも利用可（確認あり） |
| **Bot が無反応なのは連携不足？** | **別問題**のことが多い → **ルーム承認待ち**（下記 §「連携と承認の違い」） |
| **困ったら？** | 管理画面を再読込。それでもオレンジなら手動一括連携 |

## ⚠️ 「自動連携」と「ルーム承認」は別（混同注意）

| | **ルーム連携（自動連携）** | **ルーム承認（Bot 利用許可）** |
|--|---------------------------|--------------------------------|
| **何か** | 店舗 Webhook の **管理対象ルーム** として DB に登録 | そのルームで **レシート・検索等を動かすか** |
| **承認** | **不要**（既定で自動） | **必要**（新規 `C…`/`R…` は待ち） |
| **フラグ** | `room_summary_settings` への登録・`receipt_report_store_partition_key` | `bot_access_approved` |
| **操作** | Webhook 受信・管理画面同期 | 管理 Bot（@392hdime）で **許可ルーム** |

**新規**に Bot が入ったグループは、自動連携で `room_summary_settings` に載っても **`bot_access_approved = false` のまま機能が止まります**（Bot はグループに残る）。  
詳細: [LINE-USER-APPROVAL-SECURITY.md](./LINE-USER-APPROVAL-SECURITY.md) ／ 用語: [DOCS-INDEX.md](./DOCS-INDEX.md)

## 「連携」とは何か

**連携** = Webhook でメッセージを受け取った LINE ルームを、その店舗の **管理対象ルーム** として DB（`room_summary_settings`）に登録すること。

```
LINE でメッセージ送信
        ↓
店舗用 Webhook URL
        ↓
┌──────────────────────────────────────────────┐
│ 【自動連携 ON】初回受信 or 管理画面の状態取得   │
│  → room_summary_settings に登録（承認なし）    │
│  → 売上レポート送信先・店舗権限の対象になる       │
└──────────────────────────────────────────────┘
```

---

## 自動連携のタイミング

| トリガー | 処理 |
|----------|------|
| **Webhook 受信** | `line-webhook` が生ログ保存後、未知ルームをその `store_partition_key` に upsert |
| **管理画面の同期** | `GET /receipts/webhook-status`（`include_detected_rooms` 有効時）で検出済み未登録ルームを一括 upsert |
| **手動一括連携** | 従来どおり UI から可能（確認ダイアログあり・自動連携の補助） |

登録時の既定値は、管理画面の **新規ルームのデフォルト**（サーバー側固定）に合わせています（例: 中間・月末レポート ON、メディア ON、AI 会話返信 OFF など）。

**別店舗に既に `receipt_report_store_partition_key` が付いているルームは、自動では奪いません。**

## 画面の見方

| 表示 | 意味 |
|------|------|
| 🔴 **赤い注意ボックス**（Webhook別設定の上） | 自動連携（承認なし）が有効であることの常時表示 |
| 🟧 **オレンジの店舗カード** | 未連携が残っている（自動反映待ち・手動が必要・別店舗登録など） |
| 🟩 **緑のカード** | 連携済みで未連携 0 |

## 連携しない／できない場合

`RECEIPT_ROOM_AUTO_LINK=0` のとき、または次のときは **自動連携されません**。

| 状況 | 結果 |
|------|------|
| 自動連携 OFF | 従来どおり手動のみ |
| **別店舗に既登録** | スキップ（店舗取り違え防止） |
| まだ一度も Webhook 受信していない | 検出ルームなし → 登録されない |

手動連携・レシートの Webhook 受信・売上テーブルへの保存は、自動連携 OFF でも（別途）動作します。

---

## トラブルシュート

```
売上レポートが来ない
    → RECEIPT_ROOM_AUTO_LINK=0 ではないか確認
    → 管理画面を再読込（バックグラウンドで自動連携が走る）
    → オレンジが残る → 手動「一括連携」

意図しないルームが登録された
    → Webhook URL・参加グループを確認
    → ルーム削除後も再受信で復帰し得る → グループ側の整理 or AUTO_LINK=0
```
