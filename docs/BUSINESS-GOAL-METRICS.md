# 目的に応じた分析とKGI・KPI・KFI

2026-09-21。KGI・KPI・KFIは**目標と行動を管理する枠組み**であり、売上分析の方法そのものの代わりではない。KFIは本アプリでは**現場で実行・管理する行動指標**であり、重要財務指標の意味ではない。

質問 → 期間 → 分析手法 →（KPI/粗利なら売価・原価、任意でKGI）→ 選んだ手法の知識パックだけを読んで分析する。倉庫は [management-warehouse](./management-warehouse/README.md)。ベクトル検索で理論全文を載せない。

## 分析の順番

質問・目的を理解する → 候補の分析手法を利用者が選ぶ → 選んだ方法で分析する → 改善策が必要な場合にだけKPIへ落とし込む。手法を毎回全部並べない。粗利が未登録でも、目標として選んだ場合は推測値を出してよい。

| 確かめたいこと | 適した角度 | 原価 |
|---|---|---|
| 何が売上を支えているか | 売上構成比のABC | 不要 |
| なぜ売上が増減したか | 客数・客単価・購入点数・商品構成の分解 | 不要 |
| いつ、何が売れるか | 時間帯・曜日・月別 | 不要 |
| 何が一緒に買われるか | 同時購入・組合せ | 不要 |
| イベント日の特徴は何か | 曜日・営業時間などの条件をそろえた比較 | 不要 |
| 売れていても利益が残るか | 人気と採算の組合せ | 必要 |
| 改善施策をどう管理するか | KGI・KPI・KFI | 行動記録は別途 |

売上構成のABCは累積寄与だけでよい。人気×収益性の分類は原価または粗利が無ければ作らず「採算は未判定」とする。原価不足を理由に売上ABCまで止めない。

導入相談（例: クロワッサン）や新しい施策は、先に既存の近い商品の販売実績・時間帯・同時購入・構成への影響を調べる。施策自体の実績は無いので数値未確認で止めない。販売分析・目標・見込みを求められたときは、今の店舗売上と類似商品の推移からコードが保守・標準・強気の寄与率・上積みを出す。推測は【仮定(シナリオ)】であり実績ではない。

## 改善管理のときだけ使う対応

```text
KGI: 店舗売上などの最終成果
├─ KPI: 来客数 → KFI: 店頭案内・販促実施・リピート案内
├─ KPI: 客単価/セット率 → KFI: おすすめ・追加注文・ペアリングの提案
└─ KPI: 回転率/席稼働率 → KFI: 提供時間の記録・予約枠の見直し
                       ※共有席や未導入の予約経路は測定可否を先に確認
```

- 改善策・打ち手を書く場合だけ「KGI・KPI・KFI」の対応を含める。観察・照会では付けない。固定見出し指定時は見出しを増やさず、既存の最後の施策欄へ入れる。
- そのときに限り、KGIの目標との差から原因候補のKPIを絞り、改善するKFIを選ぶ。検証は逆方向に、KFIの実行→KPIの変化→KGIへの寄与を同条件・同期間で追う。相関を因果と断定しない。
- 明示KPIでは①KGI（数値と期限。無ければ未設定）②現状実績とのギャップ③プロセス分解④現場が動かせる最重要プロセス（CSF）を1つ⑤その数値目標だけをKPI⑥測れて動かせるか⑦悪化時はいつ・どれくらい・何をする・誰が決める。指標の羅列はしない。
- 飲食では売上だけで店長や施策を評価しない。客数×客単価に分解し、客単価は商品点数まで見る。人時売上は総労働時間があるときだけ。月末だけの振り返しにせず、日次・時間帯の先行指標を優先する。業界の合格ラインは当店目標にしない。
- 利用者の目的を優先する。目標値・期限が無ければ未設定とし、KGI候補を合意済み目標にしない。KFIに担当候補・実施タイミング・記録方法/単位を付ける。
- 新商品の改善管理: 店頭案内・セット提案件数（KFI）を記録し、販売数・セット率（KPI）と商品売上（KGI候補）への寄与を検証する。既存商品の置換が未確認なら商品売上を店舗全体の純増売上と呼ばない。

## 採算と効率の確認

財務・採算はKFIと分け、必要に応じて原価・粗利・追加人件費・廃棄・損益分岐を確認する。販売数が増えても採算が不明なら「採算は未判定」と必要な記録を示す。

- 売上は客数×客単価。回転率・席稼働率は客数の説明要因であり、さらに掛け合わせない。
- FL率とFLRコスト率は家賃を含むかが異なる。食材費・人件費・家賃・売上の期間/税区分をそろえる。
- 歩留まり率とロス率、回転率と席稼働率、粗利と最終利益は区別する。
- 新客/リピート、予約、商品別原価、坪数/席数などは提供データと既存の利用可能期間に限る。共有席を自店席とみなした回転率や、未登録原価からの人気×収益性ABC/合成原価率を作らない。
- 説明用に提示された目標率・金額・回転数を当店の実績・標準値・合意済み目標へ転用しない。

## 数値の境界

3概念への言及だけでは試算を起動しない。既存の明示依頼・認可・構造化前提の検証を維持する。

- 入力前提は【仮定(入力)】として参照し、未入力や実績へ読み替えない。
- 明示的な試算依頼ではコードの保守・標準・強気をKGI候補/KPI/採算へ対応づける。後続の[整合性監査](./ANALYSIS-INTEGRITY-AUDIT.md)で基準値・丸め・採算表示・試算同意の境界を修正した。
- KFIの行動件数/提案率は現在の試算器では未計測・数値目標未設定。販売目標から架空の声かけ数などを逆算しない。
- 【実績】【仮定(入力)】【仮定(シナリオ)】を保ち、実績表と仮定の試算表を分ける。達成率や不足額も正本の数値が無ければ作らない。
