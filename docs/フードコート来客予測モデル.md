## 1. 目的
- イベント・天気・曜日から**日次の来客数・売上を見通し**、仕入・人員配置・メニュー/価格の判断に使う。
- 「その日だけの再集計」ではなく、**蓄積したデータから学習し続けて精度が上がる**仕組みにする（貯まるほど賢くなる）。

## 2. モデル（売上＝客数×客単価 を土台）
客数の推定には2つのモデルを毎晩バックテストし、精度が良い方を自動採用する（v2から選択指標は売上WAPE。3章参照）。
客単価(spend)は全期間中央値固定をやめ、**イベント種別・天気で調整する動的モデル(spend-model-v1)** で予測する（2-C）。この客単価予測は乗算モデル／GLMの両方の売上予測に共通で使う。

### 2-A. レガシー乗算モデル（mult-factor-v3）
ベース水準に各要因の係数を掛ける乗算モデル。

```
予測客数 = ベース客数(meanG) × 曜日係数[曜日] × イベント/会場×客層係数[種別] × 天気係数[雨/晴]
予測売上 = 予測客数 × 予測客単価(spend-model-v1・2-C)
```

- **ベース客数 meanG**: 実績客数の平均。
- **曜日係数**: 各曜日(月〜日)の平均客数 ÷ 全体平均。
- **イベント/会場×客層係数（venue-segment-v1）**: 種別ごとの平均客数 ÷ 全体平均。種別は優先順で1つに決める。東京ドーム本体（`pro`/`live`/`dome`）とPV（`soccer_pv`/`japan`/`sports`）に加え、小ホールは `hall_kanadevia`（カナデビアホール=ライブ/舞台中心・若年層）、`hall_korakuen`（後楽園ホール=格闘技/ボクシング中心・中年男性層）、`hall_other`（プリズム/ラクーア/その他）に分ける。
- **天気係数**: 雨の日／雨でない日それぞれの平均客数 ÷ 全体平均。
- **収縮(shrink)**: サンプルが少ない係数は「1（影響なし）」へ寄せる。`係数 = (n×生係数 + K×1)/(n+K)`、K=4。少データでの暴れを防ぐ。
- AI解説（`foodcourt_forecast_factors`の`wday_factors`等）は、勝敗に関係なく**常にこのモデルの係数**を使う（解釈しやすい「倍率」の形を保つため）。

### 2-B. ポアソン回帰GLM（glm-poisson-v5）
客数はカウントデータのため、対数線形モデル（ポアソン回帰・IRLSで最尤推定）で表す。

```
log(予測客数) = 切片 + 曜日ダミー(基準=月) + イベント/会場×客層ダミー(基準=none)
              + 雨ダミー + log(1+降水量mm) + 猛暑ダミー(最高気温≥30℃)
              + log(1+予想動員数) + トレンド(標準化した経過日数)
              + 交互作用(土日×大型 + 雨×大型 + 猛暑×大型イベント)
              + トレンド二次項 + 年周期季節性(sin/cos)
予測売上 = 予測客数 × 予測客単価(spend-model-v1・2-C、学習ウィンドウ内の実績から算出)
```

- **予想動員数**: イベントの規模を連続値として直接反映できる（乗算モデルは種別の粗い分類のみ）。値は`tokyo_dome_events.expected_attendance`（下記4章参照・自動取得元には無いため手入力）。
- **会場×客層(v3)**: `foodcourt_daily_features` の `has_dome_main` / `has_kanadevia` / `has_korakuen` から小ホールを分割し、カナデビア（ライブ・若年層）と後楽園（格闘技・中年男性層）の違いを別ダミーで学習する。
- **交互作用(GLM v4・interaction-v1)**: 主効果だけでは表せない「条件の重なり」を明示的に足す。大型イベント＝東京ドーム本体系（`pro`/`live`/`dome`）とし、`土日×大型` / `雨×大型` / `猛暑×大型` の3項を追加。フル曜日×イベント(6×9)は小データで過学習するため主要3項に絞り、リッジがスパースな交互作用列を自然に0（＝交互作用なし）へ寄せる。
- **季節性・非線形トレンド(GLM v5・season-trend-v1)**: トレンド二次項 `trend^2` で開店効果の飽和/加速を表現し、年周期sin/cos（2列）で季節波を表す。月別ダミー12本より小データに強く、リッジによりデータ不足時は0（＝季節性/非線形なし）へ寄る。前年同曜日比は1年蓄積後に有効化する別施策。
- **トレンド**: 学習データの先頭日からの経過日数を標準化して説明変数に加える。開店直後で客数が伸び続けている段階の「地に足のついた」成長をベース客数の固定平均より正確に捉える。
- **リッジ正則化(λ)**: 係数を0（＝乗算モデルでいう「1倍＝無効果」に相当）へ寄せる、shrinkの統計的に裏付けのある一般化。λの強さは固定値ではなく、下記3章のループで複数候補をバックテストし自動選択する。
- IRLS(反復重み付き最小二乗)で最尤推定。曜日×イベント等の交互作用項は未実装（今後の強化・9章参照）。
- **天気(v2)**: 従来の雨フラグに加え、`log(1+降水量mm)`（雨量の強さ＝連続値）と `猛暑フラグ(最高気温≥30℃)` を説明変数に追加。降水量・気温は `foodcourt_daily_features`（元は `weather_daily`）から取得。

予測区間(low/high)は、採用されたモデルのバックテスト誤差率(MAPE)を幅に使う（無ければ暫定±25%）。

### 2-C. 客単価モデル（spend-model-v1・v2で追加）
従来は「売上＝予測客数×全期間中央値客単価」で単価を固定していたが、イベント日はドリンク/デザート比率などで客単価が動くため、客単価も条件で予測する。

```
予測客単価 = 中央客単価(baseSpend)
           × イベント/会場×客層倍率[種別] … pro/live/dome/hall_kanadevia/hall_korakuen/hall_other/soccer_pv/japan/sports/none
           × 天気倍率[hot/rainy/normal]   … hot=最高気温≥30℃, rainy=雨, normal=それ以外
```

- 各倍率は「該当条件の中央客単価 ÷ 全体中央客単価」を収縮したもの。客単価は客数より少データで暴れやすいため、客数係数より強め(K=6)に1倍へ寄せ、さらに **0.65〜1.45 の範囲に安全クリップ**する。
- 乗算モデル・GLMのどちらが採用されても、この客単価モデルを共通で使う（売上MAPE/WAPEに直接効く）。
- 係数は `foodcourt_forecast_factors.model_selection.spend_model`（jsonb）に保存し、AI解説からも参照できる。

特徴量の出所は view `foodcourt_daily_features`（日付ごとにイベント有無/種別・天気・曜日・予想動員数が1行）。実績は `foodcourt_daily_facts`（is_base=true＝MARUGO S）。

## 3. 「学習して賢くなる」仕組み（モデル自動選択ループ）
- **毎日5:00**に、その時点の**全実績**から両モデルの係数を学習し直す → 推定が安定し精度が上がる。
- **自己採点（バックテスト）**: 「その日より前のデータだけで学習→当日を予測」を全期間で回す**拡張窓バックテスト**で、ズルなし(out-of-sample)の誤差を算出。v2から **WAPE を主指標**、MAPE/MAE を補助指標として客数・売上それぞれで記録する。
  - **WAPE**（加重絶対誤差率）= `Σ|予測−実績| / Σ実績`。MAPEと違い実績の小さい日で誤差率が跳ね上がらず、売上・客数の大きい日を自然に重く扱う＝経営影響に近い。
  - **MAE**（平均絶対誤差）= `mean(|予測−実績|)`。誤差率でなく実数（客数=人／売上=円）の平均ズレ。
- **λの自動選択**: GLMのリッジ強度λ（候補: 1/2/4/8/16）ごとにバックテストして**売上WAPE**を比較し、最も当たるλを採用（データが多い場合は計算量を抑えるため粗いストライドで評価）。
- **モデルの自動選択(v2)**: 選ばれたλのGLMと、レガシー乗算モデルを同じ拡張窓バックテストで比較し、**直近ホールドアウトの売上WAPE**が小さい方を**その晩の本番予測に採用**する（データ不足時は全期間売上WAPEにフォールバック）。これが「誤差実績を使って次の予測方法そのものを変える」閉じたループであり、データ量が増えるほど（現状は小データでレガシーが有利でも）GLMが自然に有利になっていく想定。
- 過去日は「採用モデルの予測 vs 実績(actual)」を保存 → 画面・AIが精度を確認でき、**Nが増えるほど誤差が下がる**のが見える。
- どちらが採用されたかは`foodcourt_forecast_factors.model_selection`（`{chosen, glm_wins, glm_lambda, selection_metric:"sales_wape", legacy_wape_sales, glm_wape_sales, legacy/glm の mape/mae, spend_model, …}`）と、`foodcourt_forecast_history`（`model_version` に加え v2 で `wape_guests/wape_sales/mae_guests/mae_sales` とその rolling を追加。進化トラッキング・[foodcourt-evolution.html](../foodcourt-evolution.html)）で確認できる。

## 4. データ構造
| テーブル/関数 | 役割 |
|---|---|
| `foodcourt_daily_facts` | 日次×全11テナントの実績（客数/売上/客単価）。is_base=MARUGO S。学習データ本体。 |
| `foodcourt_daily_features`（view） | 日付ごとの特徴量（曜日・イベント種別・会場フラグ `has_dome_main/has_kanadevia/has_korakuen`・天気・`precipitation_mm`・`temp_max`・`max_expected_attendance`）。過去=学習／未来=予測入力。 |
| `forecast_predictions` | 予測の保存。`(target_date, tenant_name, metric)` 一意。metric=`guests`/`sales`。predicted/predicted_low/predicted_high/actual/model_version/features。 |
| `tokyo_dome_events.expected_attendance` | 予想動員（最強ドライバー）。公式発表または手入力だけを入れる。会場収容からの推定値は保存しない。入力手段は5章参照。 |
| `foodcourt_forecast_factors.model_selection` | その晩どちらのモデル(レガシー/GLM)を採用したか・λ・選択指標(sales_wape)・両モデルのWAPE/MAPE/MAE・客単価モデルを記録（透明性用。予測自体には影響しない）。 |
| `foodcourt_forecast_history` | 毎晩の進化履歴。v2で `wape_guests/wape_sales/mae_guests/mae_sales` と `rolling_wape_*` / `rolling_mae_*` を追加（migration `20260716050000_foodcourt_forecast_wape_mae.sql`）。 |

`model_version`は`mult-factor-v3`（レガシー採用時）または`glm-poisson-v5(lambda=N)`（GLM採用時）。AI解説用の`foodcourt_forecast_factors`の係数(`wday_factors`等)は常にレガシー乗算モデルのもの。

## 7-E. GLM v5（季節性・非線形トレンド）実装メモ（2026-07-16）
2026-07-16に #8/#9 のうち「いま安全に入れられる部分」を GLM v5 として実装し、本番反映（`foodcourt-forecast-cron` deploy、手動実行で `forecast_predictions` 86行 upsert）。

- #8 季節性: 年周期sin/cos（2列）で実装。月別指数より少列で、小データではリッジにより0へ寄る。前年同曜日比は1年分の実績が必要なため、データ蓄積後に別途有効化する。
- #9 トレンド非線形化: 標準化トレンドの二次項 `trend^2` を追加し、開店効果の飽和/加速を表現。
- GLM: `glm-poisson-v5(lambda=N)`
- 乗算モデル: `mult-factor-v3` のまま。
- 本番検証: `glm-poisson-v5(lambda=16)` の売上WAPEは 51.0%、乗算v3の売上WAPEは 33.5%。現時点ではモデル選択ループにより乗算v3を継続採用。

## 8. 限界・前提
- 小N（現状15日規模）では精度は発展途上。**数十日〜数ヶ月の蓄積で安定**する。
- 予想動員数は**手入力**（自動取得元には無い）。入力が無いイベントは`log(1+0)=0`＝動員数の効果は乗らない（種別ダミーのみで推定）。
- GLMは曜日×イベント等の**交互作用を未実装**（9章参照）。
- 未来日の**他店実績は予測時点で不明**＝他店データは過去パターン学習には使えるが未来予測の直接入力には使わない。
- 客単価はv2でイベント/天気別に動的化したが、小Nで暴れやすいので強めに収縮・安全クリップしている。条件別サンプルが増えるまでは「方向性の反映」に留める。
- WAPEは売上規模の大きい日を重く扱うため経営判断には向くが、小さい日の外れを軽く見る。MAPE/MAEも併記し、用途別に読む。
