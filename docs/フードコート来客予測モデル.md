# フードコート 来客予測モデル（学習型）設計・運用ドキュメント

対象: MARUGO S（東京ドーム内フードホール「FOOD STADIUM TOKYO」）の来客数・売上予測。
種別: 自己再学習型のルールベース予測（フェーズ1）。毎日、蓄積実績から係数を学習し直し、データが増えるほど精度が上がる。
初版: 2026-06-24。関連: [フードコート売上分析_設計書.md](フードコート売上分析_設計書.md)（分析フレームワーク／本モデルはそのSTEP9の実装）。

---

## 1. 目的
- イベント・天気・曜日から**日次の来客数・売上を見通し**、仕入・人員配置・メニュー/価格の判断に使う。
- 「その日だけの再集計」ではなく、**蓄積したデータから学習し続けて精度が上がる**仕組みにする（貯まるほど賢くなる）。

## 2. モデル（売上＝客数×客単価 を土台）
客数を、ベース水準に各要因の係数を掛ける**乗算モデル**で表す。

```
予測客数 = ベース客数(meanG) × 曜日係数[曜日] × イベント種別係数[種別] × 天気係数[雨/晴]
予測売上 = 予測客数 × 中央客単価(spend)
```

- **ベース客数 meanG**: 実績客数の平均。
- **曜日係数**: 各曜日(月〜日)の平均客数 ÷ 全体平均。
- **イベント種別係数**: 種別ごとの平均客数 ÷ 全体平均。種別は優先順で1つに決める＝`pro`(プロ野球) ＞ `live`(ライブ) ＞ `other`(その他イベント) ＞ `none`(開催なし)。
- **天気係数**: 雨の日／雨でない日それぞれの平均客数 ÷ 全体平均。
- **収縮(shrink)**: サンプルが少ない係数は「1（影響なし）」へ寄せる。`係数 = (n×生係数 + K×1)/(n+K)`、K=4。少データでの暴れを防ぐ。
- 予測区間(low/high)はバックテスト誤差率(MAPE)を幅に使う（無ければ暫定±25%）。

特徴量の出所は view `foodcourt_daily_features`（日付ごとにイベント有無/種別・天気・曜日が1行）。実績は `foodcourt_daily_facts`（is_base=true＝MARUGO S）。

## 3. 「学習して賢くなる」仕組み
- **毎日5:00**に、その時点の**全実績**から上記係数を学習し直す → 推定が安定し精度が上がる。
- **自己採点（バックテスト）**: 「その日より前のデータだけで学習→当日を予測」を全期間で回す**拡張窓バックテスト**で、ズルなし(out-of-sample)の誤差率 **MAPE** を算出。
- 過去日は「予測 vs 実績(actual)」を保存 → 画面・AIが精度を確認でき、**Nが増えるほど誤差が下がる**のが見える。

## 4. データ構造
| テーブル/関数 | 役割 |
|---|---|
| `foodcourt_daily_facts` | 日次×全11テナントの実績（客数/売上/客単価）。is_base=MARUGO S。学習データ本体。 |
| `foodcourt_daily_features`（view） | 日付ごとの特徴量（曜日・イベント種別・天気）。過去=学習／未来=予測入力。 |
| `forecast_predictions` | 予測の保存。`(target_date, tenant_name, metric)` 一意。metric=`guests`/`sales`。predicted/predicted_low/predicted_high/actual/model_version/features。 |
| `tokyo_dome_events.expected_attendance` | 予想動員（最強ドライバー。現状データ無し＝今後の強化点）。 |

`model_version = 'mult-factor-v1'`。

## 6. 運用・点検
- 自動実行: 毎日 JST5:00（イベント取得cron 04:10 の後）。`net.http_post` + pg_cron。
- 手動点検（dry_run・保存しない）:
  `GET /functions/v1/foodcourt-forecast-cron?dry_run=1`（anonキーのヘッダ要）→ history_days / backtest_days / mape_guests / mape_sales / upcoming / factors を返す。
- 手動実行（保存する）: 同URLを dry_run なしで叩く。
- 確認SQL: `select target_date,metric,predicted,predicted_low,predicted_high,actual from forecast_predictions where tenant_name='MARUGO S' order by target_date;`

## 7. 初期実績（2026-06-24 時点）
- 学習15日・バックテスト11日。MAPE **客数±36%／売上±45%**（小データで高め＝想定どおり。日々の蓄積で低下していく）。
- 学習された係数の例: 曜日＝土1.20/日1.35（週末高い）、イベント＝プロ野球1.39（押し上げ）/ライブ0.79、天気＝雨1.10。

## 8. 限界・前提
- 小N（現状15日）では精度は発展途上。**数十日〜数ヶ月の蓄積で安定**する。
- 動員数(expected_attendance)が未取得＝イベントの「規模」を係数に反映できていない（種別のみ）。
- 未来日の**他店実績は予測時点で不明**＝他店データは過去パターン学習には使えるが未来予測の直接入力には使わない。
- 客単価はイベント非依存の中央値で固定（イベント別の単価差は未反映）。

## 9. 今後の強化（精度を上げる順）
1. **動員数の取込**（最強ドライバー）: events に expected_attendance を入れ、規模を係数化。
2. **会場×客層別**の係数（東京ドーム/カナデビア/後楽園、野球/ライブ/格闘技で来店動機が違う）。
3. **客単価のイベント別化**（女性中心ライブ＝デザート/ドリンクで単価変動 等）。
4. フェーズ2: 回帰/勾配ブースティング(GBDT)で交互作用・非線形を取り込み。
5. 季節性（月別指数）・前年同曜日比（1年蓄積後）。
