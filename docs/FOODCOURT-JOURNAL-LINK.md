# フードコートQ&Aとジャーナルの連携

2026-09-21。対象は「データに質問」の通常Q&AとKPI試算。Journal深掘りAPI・フードコートの日次/期間/週次サマリーの取得方式は変更しない。日次/期間キャッシュは `foodcourt-analysis-ai-v30-plausibility-check`。

## 取得と出典

1. 認証済みの店舗だけを対象に、日別/月別売上、POSジャーナル、共有Journalレポート、自店レシート、比較表から保存範囲を確認する。「全期間」に固定の開始日を埋め込まない。
2. Journal AIと同じ統一売上ローダーを使用。項目別に明示手修正 > 同期済みジャーナル > 自店レシート。月計だけの補完と日別記録を区別する。明細だけ保存され統一売上に未同期の場合は、統一売上の記録なしを明示し、商品明細を総売上の代わりに合算しない。
3. POS原本と共有Journalレポートを既存の優先ルールで日付単位に統合し、取消・調整を処理する。日計・会計合計・商品合計の照合に失敗した日は商品分析から除外する。エラーは空データと偽らず503で停止する。
4. 専門AI、統合AI、品質評価、コードによる数値監査へ実績を渡す。回答/履歴に統一売上と商品明細それぞれの期間・件数を保存する。過去回答の数値で今回の実績を上書きしない。

## KPIに使える実績と限界

| 実績 | 使い方 | 混同しないもの |
|---|---|---|
| 商品別販売数・売上・販売日数 | 主力商品の把握、既存商品の販売量の確認 | 新商品の予測需要・粗利 |
| 商品購入会計数 ÷ 検証済み会計数 | 購入会計比率 | 来客の購入率・提案成功率 |
| 会計時刻別の件数・売上・商品数量 | 時間帯別の販売傾向 | 注文時刻・来店時刻・作業時間 |
| 同一会計内の商品組合せ | 併売の観測 | セット販売の実績・施策の因果効果 |

商品別売上・時間帯・同時購入は、主力把握・増減分解・導入相談の観察に先に使う。通常Q&Aは期間確定のあと、質問内容から候補にした分析手法を選択する。選んだ角度だけを実行する。選んだ手法の短い知識パックだけを分析前に読む（[マネジメント知識倉庫](./management-warehouse/README.md)）。同じ会話の追加質問は前回の回答を本文とし、手法も引き継ぐ。全体レポートの書き直しではない。「最初から」「やり直して」で新規分析に戻る。金額は今回の集計。粗利・目標を選んだ場合、原価未登録でも【仮定(シナリオ)】の推測値で目標を出してよい。その前に想定売価と予想原価を確認する（入力欄・チャット・全部お任せ）。任意で最終目標KGI。客単価や類似SKUの単価を新商品の店頭価格にしない。改善策を管理する段階になってから、販売量/時間帯/併売をKPI、提案・製造・案内をKFIとして対応づける。ジャーナルから原価、人件費、廃棄、提案回数などを逆算して実績扱いしない。KFIは別途実行記録と照合する。売上構成のABCに原価は不要。人気×採算の分類だけ原価を要求する。

新商品・新しい施策の販売分析・販売戦略・販売見込み、または明示的な試算依頼では、類似/対象商品の1日あたり販売と月次売上推移から保守・標準・強気の見込み個数をコードが計算する。標準は観測された日次個数。複数月あれば月ごとの1日あたり店舗売上の最小〜最大比で幅を付ける。1か月だけなら既存シナリオの購入率比（8/12・18/12）で幅を付ける。今の店舗日次売上を分母にした寄与率と、置き換えを見込んだ上積みも同じ3シナリオで出す。これは【仮定(シナリオ)】であり実績ではない。施策自体の実績が無いことを数値未確認とはしない。売価・原価は入力または3シナリオ仮置き。損益分岐・撤退ラインは従来の確定計算を併記する。時間別配分は見込み個数を観測済み会計の時間構成で整数配分する。合計は日次目標と一致する。時刻不明会計は配分の重みから除く。シナリオ表は表の直上に注釈1行、セルへ【仮定(シナリオ)】を複製しない。試算が動いたら回答末尾にコードが表を付ける。

## 上限・表示・セキュリティ

- 自店売上は全対象月の集計を保持し、日別詳細は各範囲の直近366日。省略件数を明示する。対象範囲は既存の最大3660日検証を利用する。
- 商品は売上上位30件＋質問に商品名が一致する最大10件、併売は上位20組。20種類を超える会計は組合せ集計だけから除外し、除外件数を示す。抜粋にない商品を販売なしと断定しない。
- 比較表は最大500件・日別詳細45日という別の上限。順位・シェア・イベント/天気相関は比較表で根拠がある期間だけ。自店の全期間へ外挿しない。
- 未取得日を0円/休業日とはしない。欠けた客数・組数や税額は未確認とする。原本の商品金額と統一売上は一致するとは限らず、足さない。
- ブラウザから受け取るのは検証済み期間と許可済み入力前提だけ。認可済み店舗の原本をサーバー取得し、伝票番号・テーブル番号・生テキストをAIへ渡さない。DBスキーマ・アクセス権・保存済み売上は変更しない。
- 利用者は画面を更新し、全期間で再質問する。保存済み回答・出力済みPDFは自動変更しない。Q&Aの新しいPDFは分析例レイアウト。「この回答を出力」と「会話をPDF」。
