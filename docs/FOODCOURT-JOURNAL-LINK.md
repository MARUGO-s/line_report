# フードコートQ&Aとジャーナルの連携

2026-09-20。対象は「データに質問」の通常Q&AとKPI試算。Journal深掘りAPI・フードコートの日次/期間/週次サマリーの取得方式は変更しない。

## 取得と出典

1. 認証済みの店舗だけを対象に、日別/月別売上、POSジャーナル、共有Journalレポート、自店レシート、比較表から保存範囲を確認する。「全期間」に固定の開始日を埋め込まない。
2. Journal AIと同じ統一売上ローダーを使用。項目別に明示手修正 > 同期済みジャーナル > 自店レシート。月計だけの補完と日別記録を区別する。明細だけ保存され統一売上に未同期の場合は、統一売上の記録なしを明示し、商品明細を総売上の代わりに合算しない。
3. POS原本と共有Journalレポートを既存の優先ルールで日付単位に統合し、取消・調整を処理する。日計・会計合計・商品合計の照合に失敗した日は商品分析から除外する。エラーは空データと偽らず503で停止する。
4. 専門AI、統合AI、品質評価、コードによる数値監査へ実績を渡す。回答/履歴に統一売上と商品明細それぞれの期間・件数を保存する。過去回答の数値で今回の実績を上書きしない。

## KPIに使える実績と限界

| 実績 | 使い方 | 混同しないもの |
|---|---|---|
| 商品別販売数・売上・販売日数 | 主力商品の把握、既存商品の販売量の確認 | 新商品の予測需要・粗利 |
| 商品購入会計数 ÷ 検証済み会計数 | 購入会計比率 | 来客の購入率・提案成功率 |
| 会計時刻別の件数・売上・商品数量 | 時間帯別の販売傾向 | 注文時刻・来店時刻・作業時間 |
| 同一会計内の商品組合せ | 併売の観測 | セット販売の実績・施策の因果効果 |

KGIの売上 → KPIの販売量/時間帯/併売 → KFIの提案・製造・案内という関係に利用する。ただしジャーナルから原価、人件費、廃棄、提案回数などを逆算して作らない。KFIは別途実行記録と照合する。

明示的な試算依頼時のみ、保守・標準・強気それぞれの日次目標を観測済み会計の時間構成で整数配分する。合計は日次目標と一致するが、将来の新商品も同じ時間構成で売れるという【仮定(シナリオ)】であり、需要予測や通常日の実績ではない。時刻不明会計は配分の重みから除く。

## 上限・表示・セキュリティ

- 自店売上は全対象月の集計を保持し、日別詳細は各範囲の直近366日。省略件数を明示する。対象範囲は既存の最大3660日検証を利用する。
- 商品は売上上位30件＋質問に商品名が一致する最大10件、併売は上位20組。20種類を超える会計は組合せ集計だけから除外し、除外件数を示す。抜粋にない商品を販売なしと断定しない。
- 比較表は最大500件・日別詳細45日という別の上限。順位・シェア・イベント/天気相関は比較表で根拠がある期間だけ。自店の全期間へ外挿しない。
- 未取得日を0円/休業日とはしない。欠けた客数・組数や税額は未確認とする。原本の商品金額と統一売上は一致するとは限らず、足さない。
- ブラウザから受け取るのは検証済み期間と許可済み入力前提だけ。認可済み店舗の原本をサーバー取得し、伝票番号・テーブル番号・生テキストをAIへ渡さない。DBスキーマ・アクセス権・保存済み売上は変更しない。
- 利用者は画面を更新し、全期間で再質問する。保存済み回答・出力済みPDFは自動変更しない。
