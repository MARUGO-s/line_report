Journal Report の使い方

POS電子ジャーナル（.jnl / .lzh）から売上レポートを作り、店舗ごとにクラウドへ保存し、AI分析・チャットで振り返るためのアプリです。変換そのものは端末内で行い、保存とAIは認証付きのクラウドAPI経由です。

1. ログインと店舗選択

  1. 画面上部で管理トークンを接続するか、LINEの最新リンクから開きます。
  2. 右上の店舗ドロップダウンで対象店舗を選びます。
  3. 店舗用ログインは自店のみ（他店は選べません）。
  4. 管理者は店舗を切り替えて横断閲覧・分析できます（「店舗横断サマリー」も利用可）。

2. ジャーナルの取り込み

  1. 「変換」タブで .lzh / .jnl（または月フォルダ）をドラッグ＆ドロップ、または選択します。
  2. .lzh は自動解凍し、制御コード除去・文字コード変換のうえ売上を集計します。
  3. 読込後はレポート作成〜クラウド保存まで自動実行されます（未ログイン時は保存できません）。
  4. 必要に応じて商品コード分類（フード／ドリンク等）を店舗別に調整できます。

3. レポート・履歴

  • 保存済みレポート … 日別・月間レポートを店舗スコープで一覧・再表示・削除
  • 売上予測 / 予測履歴 … 保存データに基づく予測と実績比較
  • AI分析履歴 … レポートに対するAI分析結果の履歴
  • AIチャットPDF履歴 … チャット回答を「PDFにする」したときの質問＋回答一覧

4. AI分析・AIチャット

  1. レポート画面の「AI分析」でコンサルティングレポートを生成できます（自動で履歴保存）。
  2. 「AIチャット」では保存済みレポートを根拠に質問できます（期間比較・推移・改善案など）。
  3. 回答下の「📄 PDFにする」で印刷用表示を開き、同時に質問と回答をクラウドへ保存します。

5. .jnl / .lzh について

POSが出す電子ジャーナル（.jnl）は制御コード付きのバイナリログです。.lzh はその圧縮書庫で、本アプリが自動解凍します。変換の内部手順は「解凍 → 制御コード除去 → デコード → レコード整理 → 売上集計／レポート化」です。

6. データの扱い（重要）

  • 解析処理は端末内。レポート・AI分析・チャットPDF履歴・予測は選択店舗のクラウド領域（store_partition_key）に保存されます。
  • 店舗用ログインでは他店データにアクセスできません。管理者のみ横断できます。
  • 公開ページから業務テーブルへ直接アクセスはしません（admin-api＋認証経由）。

.jnl / .lzh を読み込むと、選択中の店舗へ売上レポートを自動保存します。解析は端末内、保存とAIは認証付きクラウドAPI経由です。
